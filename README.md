# 磨轴 · Friction → Axis

把反复出现的摩擦，磨成能管住下一次的「轴」。

**一句话：轴是给下一次立的约定，不是对过去的总结。**

所以每条轴都必须可违约、必须带失效条件。写成"知识"它当场就死了——知识写完就结束，约定要等下一次开奖。

---

## 为什么只有一个脚本

因为它要能**单独运行**。

不依赖记忆系统、不依赖打扫脚本、不依赖任何别的插件。你只装这一个，它照样能用。

- 一个文件：`axis.py`（只用 Python 标准库，不联网）
- 一个数据文件：`axes.json`（脚本旁边自动生成，`--db` 可指到别处）
- 一份说明：`SKILL.md`

## 装

```bash
mkdir -p ~/.dsh/skills/friction-axis
cp SKILL.md axis.py ~/.dsh/skills/friction-axis/
```

就是把整个目录放进 skills 目录。名字和描述会进每次会话的目录；正文按需加载。

不用 DSH 也行——它就是普通 python 脚本：

```bash
python axis.py --db my.json check
```

## 用

一次完整流程，从摩擦到轴：

```bash
# 1. 记摩擦。--root 是「把默认用了什么抽成一句抽象动作」，不是场景名。
python axis.py add "直接用了手边那个，没列备选" --scene 装环境 --root "拿熟的顶掉该用的"
python axis.py add "凭印象引用了一句，没回原文" --scene 写报告 --root "拿熟的顶掉该用的"
python axis.py add "复制了上次的配置，没看这次要什么" --scene 改配置 --root "拿熟的顶掉该用的"

# 2. 够 3 条 + 3 个场景，scan 才会把它列成"可以提"
python axis.py scan

# 3. 提炼。四件缺一不可，脚本会拦。
python axis.py promote 先问这是什么 \
  --axis "先定位这个词/这件事在哪一层，再定它是什么任务，最后才定用什么做" \
  --breaks "查不起的时候（没渠道、来不及）——那时该明说不确定" \
  --premise "有渠道可查、对方愿意等" \
  --cand "候选一：懒" \
  --cand "候选二：不知道还有别的办法" \
  --why "三次都发生在有渠道的时候，所以不是没渠道，是没去查" \
  --root "拿熟的顶掉该用的"

# 4. 动手前看
python axis.py check

# 5. 用过一次、真的拦住了，就记一次
python axis.py confirm A1 --note "这次先问了'这在哪一层'"
```

## 门槛

**同根 + 不同场景 + 至少 3 条。**

- **同根**：把「我默认用了什么」抽成一句抽象动作，能写成同一句就是同根。**不按场景分族**——按场景分，几条犯案会散成几族，每族一条样本，永远到不了门槛。
- **不同场景**：换了场合还犯同一个动作。**同一个场景犯三次，只算一条样本。**
- **3 条**：必须高于"补丁"的门槛（补丁 = 出过一次就加一条）。2 被补丁占了，所以下限是 3。

## 两种在场

- **当规则**：照它办，撞了疼。
- **当观察**：不照它办，但要提到它，撞了会犹豫一下。

**降级只退第一种，不退出场。** 退场的东西永远等不到摩擦——那是"降级"最容易掉进的死循环。

`axis.py decay` 会把 90 天没被确认的轴移到观察位，但**不删它**。

## 上限与四种结局

规则位最多 5 条，脚本会拒绝第 6 条。超了必须合并或降级。

两根轴打架时，通常说明它们是同一个更高决定的两个分支。按顺序试：**改 → 并 → 降 → 删**。

## 边界

它**不能让你不犯错**。它只做两件事：

1. 把「犯了」和「知道自己在犯」之间的时间差缩短一点
2. 让「上闸」和「提规律」有不同门槛，不至于每出一次事就多一条规矩

验它有没有用，看三个数：**规矩总数、规则位条数、补丁还在不在继续加。** 三个月后这三个数没变，那就该删掉它。
